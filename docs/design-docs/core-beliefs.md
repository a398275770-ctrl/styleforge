# 核心信念（core-beliefs）

> 这是**争议的裁决依据**。当「该不该这么做」出现分歧时，回到这份文件，而不是回到聊天记录。

## 通用操作原则（harness 工程化，源自施工图 §1/§9，长期有效）

1. 人类掌舵，智能体执行。人类不直接贡献代码行；人类负责目标、边界、验收。
2. 工程师的工作是设计环境、明确意图、构建反馈回路，而不是逐行编码。
3. 上下文是稀缺资源；给地图，不给说明书（入口文件短小稳定，指向更深的真实来源）。
4. 智能体在运行时看不到的东西，对它来说不存在。知识必须进仓库。
5. 强制不变量，不微观管理实现。规定「什么不许发生」，不规定「用什么库怎么写」。
6. 中央强制边界，本地允许自主表达；智能体产出只需正确、可维护、对后续智能体可读。
7. 纠错成本低，等待成本高：短生命周期提交 + 最小阻塞式门禁。
8. 技术债是高息贷款，小额高频偿还，禁止攒成大爆炸重构。
9. 遇到卡点先问：「缺的是什么能力？如何让它既清晰可读又可强制执行？」
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具（linter/结构测试）。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。
12. 改造存量项目时，重构不改变业务行为；行为变更必须显式登记并单独提交。

## 项目特有信念（styleforge 的第一性原则）

13. **只动一个键。** `settings.json` 是用户的资产，styleforge 只碰 `outputStyle`；扩大管理面必须先在台账立项并经用户确认。
14. **一切可回退。** 任何写操作前先备份；`uninstall` 与 `restore` 必须永远可用且不依赖网络。
15. **字节保真。** pack 内容怎么写就怎么装：CRLF 不翻译、md5 可复算、`preview --raw` 输出即安装字节。
16. **零第三方运行时依赖。** 这个工具装在用户 home 里动用户配置，行为必须完全可推理；「无聊的技术」优先。引入任何依赖需过本条裁决。
17. **平台是事实，不是假设。** 跨平台行为（`$HOME` 解析、权限、换行符）一律以实测为准，测不到的不写进承诺（D6：Python 3.10+）。

## 重构红线（施工图 §9，长期有效）

R1 保留原有业务行为｜R2 行为变更显式登记+单独提交｜R3 先护栏后动手｜R4 不做范围外优化（新问题只登记）｜R5 不删无法判断的内容（标「待核实」）｜R6 不引入不可内化的依赖｜R7 不藏信息｜R8 每一步可回滚
